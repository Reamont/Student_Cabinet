# Безопасность и ограничения

## Угрозы и защита

| Риск | Реализация |
| --- | --- |
| Подбор пароля | Хеширование стандартным Django PBKDF2; проверка через AuthenticationForm; общий DB-backed rate limit для `/login/` и `/admin/login/` |
| Чтение чужих данных по ID | Каждая личная выборка ограничена `request.user`; расписание — группой его профиля; отсутствие доступа возвращает 404 |
| Подмена владельца/роли/статуса | Белый список полей формы; владелец задаётся сервером; служебные поля не принимаются от студента |
| Доступ студента к admin | Django staff/permission checks; студенческие аккаунты не сотрудники |
| CSRF | Django CsrfViewMiddleware, токены во всех изменяющих POST-формах |
| XSS в тексте заявления | Автоматическое экранирование Django; пользовательский HTML не разрешён; CSP без внешних скриптов |
| Повторное подтверждение | Подписанный owner-bound токен формы и уникальный UUID в БД; транзакционное создание |
| Потеря заявки при рестарте | Миграции и постоянная БД; production PostgreSQL в отдельном томе |
| Кража cookies | HttpOnly сессия, SameSite=Lax, Secure при production HTTPS; срок сессии 8 часов |
| Кеш личных страниц | `Cache-Control: no-store, private` для динамических ответов |
| Clickjacking | `X-Frame-Options: DENY`, CSP `frame-ancestors 'none'` |
| Утечка секретов | Переменные окружения, игнорируемые локальные файлы, `.env.example` без рабочих значений |

В форме подписанный токен действует один час. Подпись защищает связь токена с пользователем и UUID; отправленное содержание отдельно проходит валидацию. Повторный POST с тем же ключом и другим содержимым не перезаписывает заявку.

## Вход и ограничение попыток

`LoginRateLimitMiddleware` считает все попытки POST, включая успешные: до 10 на аккаунт и до 40 на сетевой адрес за 15 минут, далее 429 и `Retry-After`. Идентификаторы хешируются HMAC с секретом приложения. Счётчики хранятся в БД, поэтому рестарт web не сбрасывает окно. Сообщение неверного входа не раскрывает, существует ли пользователь.

Ограничение по аккаунту может временно затруднить вход законному владельцу при атаке. За reverse proxy приложение не доверяет пользовательскому `X-Forwarded-For`; при текущей схеме все обращения могут иметь адрес loopback. Перед массовой публичной демонстрацией нужен лимит на nginx/edge с корректно определяемым IP, мониторинг и проверка ожидаемой нагрузки. Это ограничение прототипа, а не доказанная защита от распределённого перебора.

## Работа сотрудника и история

Сотруднику доступен защищённый Django admin. При статусах «Нужно уточнение» и «Отклонена» комментарий обязателен. Статус, история и уведомление сохраняются транзакционно. Создание и удаление студенческих заявок через admin отключены, владелец и исходный текст доступны только для чтения.

Демо-сотрудник создаётся с `is_staff` и только разрешениями просмотра/изменения заявки; это не superuser. Для новых рабочих ролей сохраняйте минимальные разрешения и не раздавайте superuser нескольким людям. Пароль сотрудника передаётся приватно отдельно от материалов жюри. В production нет фиксированного штатного пароля.

## Производственная конфигурация

- `APP_ENV=production`: отладка выключена, обязательна PostgreSQL, включены Secure cookies, перенаправление HTTPS и HSTS.
- Настройте конкретные `ALLOWED_HOSTS`, доверенные HTTPS origins и случайный `DJANGO_SECRET_KEY`.
- Секрет приложения должен быть длинным и случайным; замена секрета инвалидирует подписанные формы/сессии.
- Не открывайте Gunicorn и PostgreSQL в Интернет. nginx перезаписывает `Host` и `X-Forwarded-Proto`; доверять заголовку от любого клиента нельзя.
- Логи не включают тела POST, пароли и токены. Не включайте DEBUG, shell tracing и дампы окружения на публичном сервере. nginx access log в шаблоне отключён.
- Копии БД — с ограниченным доступом и вне единственного сервера; восстановление проверяется отдельно.

## Проверки и доказательства

Автоматизированные и браузерные результаты приводятся в `process-report.md`. Проверка изоляции должна использовать два аккаунта и реальные ID чужих записей; один только скрытый пункт меню не подтверждает защиту. HTML endpoints проверяются теми же правилами, что и API.

Скачивание справок не реализовано: следовательно, нет файла/эндпоинта, через который можно обойти проверку владельца. Добавляя загрузку, необходимо отдельно реализовать owner-check и покрыть подмену ID файла тестом. За отсутствие необязательной функции нельзя выдавать проведённый тест скачивания.

## Что не проверено и не обещается

Нет утверждения о полном отсутствии уязвимостей, соответствии законодательству или готовности к обработке настоящих персональных данных. Не проведены независимый аудит, пентест, нагрузочные испытания, проверка восстановления production, почтовая/MFA-инфраструктура и эксплуатационный мониторинг. Нет реальной электронной подписи и юридически значимых документов. Эти границы следует сохранить и в презентации.
