# Реальный процесс с использованием ИИ

## Инструменты и участники

- Codex: анализ пользовательского задания, проектирование, генерация и исправление кода, запуск команд и подготовка документов.
- Shell, Python, Git, pip и PyPI: проверка checkout, версий и установка зависимостей. Редактирование выполнялось инструментами командной строки и patch, отдельная IDE не использовалась.
- Параллельные агенты Codex: отдельные задачи интерфейса (`templates/`, `static/`), документации/развёртывания, автоматических тестов и браузерной проверки. Основной агент сохраняет ответственность за интеграцию и проверку результата. Наличие параллельных агентов не заменяет фактические тесты.
- Django test runner и Playwright с Chromium 155: фактические команды и результаты приводятся в `process-report.md`; окончательные 13 групп браузерных сценариев выполнены в Linux, 5 ноября 2026 в 09:22 МСК.
- Docker: реальная PostgreSQL 17, чистая сборка приложения, Gunicorn под непривилегированным пользователем, миграции/seed на отдельной пустой БД и локальная проверка production-настроек. Публичный HTTPS не проверялся.

Внешний генеративный API в продукт не подключался. «План на сегодня» — правила по данным пользователя. Исследования и интервью со студентами не проводились.

## Этапы и ключевые запросы

1. **Окружение.** Пользователь попросил: «Use $cloud-environment-onboarding:setup to set up this cloud environment» для `Reamont/Student_Cabinet`, `main`. Проверка установила: репозиторий пуст, удалённых refs нет. Был подготовлен базовый runtime; кода приложения тогда не существовало.
2. **Новое задание.** Пользователь приложил русское ТЗ, начинающееся словами: «Ты — ведущий разработчик и продуктовый архитектор конкурсного проекта “Цифровой деканат будущего”». В нём задано ядро, безопасность, мобильная версия, процесс и материалы для жюри. Это стало основанием создавать новый проект.
3. **Архитектура.** Основной агент выбрал Django-монолит, SQLite локально и PostgreSQL для production, без внешнего ИИ API. Приоритет — сквозной сценарий и серверная авторизация.
4. **Делегирование интерфейса.** Ключевая инструкция: «Implement all Django templates and static CSS/JS ... Work ONLY templates/ and static/. No backend edits». Были переданы названия URL и контекстов, чтобы команды не меняли одни и те же файлы.
5. **Документация.** Ключевая инструкция: «Create docs and deployment assets ... No Python app edits, no templates/static». Отдельно запрещено приписывать человеку работу, выдумывать опубликованный сайт и результаты проверок.
6. **Интеграция и проверки.** Конкретные результаты добавляются по мере реальных запусков в отчёт. Скриншоты должны получаться из работающего браузера, а не генератора изображений.

## Реальные проблемы и исправления

- Первая попытка `git ls-remote` не могла соединиться с proxy в ограниченном исполнении. Повтор через разрешённый инструмент исполнения показал успешный доступ и пустой remote. Ошибка не была истолкована как необходимость просить новый GitHub-токен.
- Изначально в repository отсутствовали README, manifests и код; продолжать настройку несуществующего приложения было невозможно. После получения нового задания создан проект, а не выдумана существующая кодовая база.
- Условия конкурса не содержат доступной официальной ссылки. В предоставленных требованиях срок работы и дедлайн подачи не указаны; даты необходимо уточнить у организатора.
- Совместимость Django 5.2 с Python 3.12 сверена по официальному исходнику release notes в репозитории Django (`stable/5.2.x/docs/releases/5.2.txt`); версии пакетов проверены через PyPI. Для контейнерной установки предусмотрена передача доверенного CA bundle через BuildKit secret без отключения TLS.
- Для развёртывания нет домена, VPS и прав владельца. Подготовлены конфигурации и инструкция; успешная локальная работа не объявляется публикацией.

Последующие ошибки и их исправления фиксируются только после воспроизведения. Неудачные подходы ради полноты рассказа не придумываются.

В ходе автоматических проверок обнаружено, что при идущем занятии отметка следующего занятия вычислялась некорректно. Расчёт текущего и следующего разделён; тест проверяет обе отметки при контролируемом времени. Также исправлен сам тест cookie: `Client.force_login` создаёт вспомогательную cookie без обычных атрибутов HTTP-входа, поэтому HttpOnly/SameSite проверяются после реального POST входа. Это исправление доказательства, а не ослабление настройки сессии.

Первый браузерный прогон искал слово «Было» вместо реального обозначения переноса зачёркнутым значением и стрелкой. Исправлен селектор теста, полный сценарий выполнен повторно. Браузерные скриншоты сохранены в `docs/screenshots/`; протокол — `docs/browser-checks.md`. Синтетические изображения и генератор картинок для доказательств не использовались.

При заключительной проверке замечено, что «План на сегодня» использовал ограниченные списки карточек главной: не более четырёх активных заявок и пяти дедлайнов. Источники плана отделены от этих визуальных ограничений, чтобы требующее ответа старое обращение не пропадало из плана. Существующий тест расширен случаями с шестью записями каждого типа; число тестовых методов осталось 31.

## Границы доказательств

Документация не подтверждает сама себя. Окончательные отметки «проверено» опираются на вывод команд, результаты тестов и реальные скриншоты. Интервью, ручной дизайн человеком, публичный адрес, российская доступность и независимый аудит не заявляются без соответствующих действий и свидетельств.

При финальном запуске тестов внутри production-образа HTTP-клиент Django получил ожидаемые HTTPS-перенаправления вместо страниц. Тестовый класс явно отделён от сетевого слоя: разрешён `testserver` и отключён redirect только внутри тестов. Рабочие production-настройки не изменялись; перенаправление HTTP → HTTPS и Secure-cookie отдельно проверены на настоящем Gunicorn. Предыдущий успешный PostgreSQL-прогон использовал локальные настройки.

PDF-экспорт сначала не смог открыть file:// из-за политики управляемого браузера. Экспортёр изменён: передаёт HTML через set_content и встраивает только проверенные скриншоты как data URI. Повторный экспорт успешно создал PDF (15 страниц A4); первая страница отрисована и просмотрена. Исходные изображения сохранены отдельно.
