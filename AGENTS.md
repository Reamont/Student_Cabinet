# Пульс Кампуса: инструкции разработчику

Конкурсный прототип вымышленного РТУ МЕМРЭА. Все данные вымышлены.

## Структура

- `campus/`: настройки Django, URL и WSGI.
- `portal/`: модель данных, формы, представления, административная панель, тесты, `seed_demo`.
- `templates/`, `static/`: серверный интерфейс на русском, без внешнего CDN.
- `scripts/dev.sh`: локальный запуск; `var/` содержит локальную БД и секреты, исключён из Git.
- `deploy/`: PostgreSQL + Gunicorn в Compose, пример nginx HTTPS.
- `docs/`: требования, процесс, доказательства и комплект для конкурса.

## Команды

Работайте в существующем checkout. Каждая облачная задача изолирована; не создавайте Git worktree, если пользователь явно этого не просит.

```sh
python3 -m venv .venv
.venv/bin/pip install -r requirements.lock
bash scripts/dev.sh
```

В другом терминале загрузите локальное окружение без вывода его значений:

```sh
set -a
. var/dev.env
set +a
.venv/bin/python manage.py check
.venv/bin/python manage.py makemigrations --check --dry-run
.venv/bin/python manage.py test
```

## Правила

- Не добавляйте настоящие персональные данные, официальные логотипы, вузовские интеграции и фиксированные пароли.
- Все персональные выборки ограничивайте текущим пользователем на сервере. Владелец и служебный статус не принимаются из формы студента.
- POST защищён CSRF; не отключайте экранирование шаблонов. Новые изменения прав доступа покрывайте тестами с двумя пользователями.
- Не показывайте секреты, содержимое `.env` и пользовательские тексты в логах или артефактах. Скриншоты — только с вымышленными данными, без паролей.
- Инициализация данных не удаляет обращения и не сбрасывает пароли. Миграции проверяйте с пустой БД.
- Сохраняйте русские подписи, текстовые статусы, видимый фокус и работоспособность при 360 px. У кнопки должно быть реальное действие.
- Новые зависимости фиксируйте в `requirements.lock`, проверяйте совместимость и лицензию.
- Production требует PostgreSQL, HTTPS, постоянного тома, закрытого порта приложения и защищённых cookies. Не включайте `DEBUG`.
- Документируйте фактические проверки и ошибки. Не приписывайте человеку, ИИ или браузеру действия, которых не было.
- Не публикуйте сайт, пароли сотрудника или конкурсную заявку без соответствующего полномочия и доступов.
